# Hyphenated chart names, then /song/<name> Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Chart files are `round-midnight.txt`; their practice sheets are `/song/round-midnight`; nothing a visitor saved, and no old link, is lost.

**Architecture:** Part 1 renames the 242 chart files (`_` → `-`), regenerates the name-keyed fixtures, sweeps
tests and docs, and adds a client plugin that moves browser storage saved under old names. Part 2 moves
`pages/song.vue` to `pages/song/[[slug]].vue`, with client-side redirects from old addresses and a prerendered
page per chart.

**Tech Stack:** Nuxt 4 (static prerender, Vercel), Vue 3, Vitest, Playwright; engine in TypeScript (`engine/`).

**Spec:** `docs/superpowers/specs/2026-10-12-song-url-design.md`

## Global Constraints

- Chart file names: `[a-z0-9]+(-[a-z0-9]+)*.txt`; the slug is the file name without `.txt`.
- `?mine=<id>`, `?new=1` and `#s=<payload>` stay on a bare `/song`.
- Practice sheets stay `noindex` and out of the sitemap; canonical is `canonicalUrl(route.path)` (self).
- Redirects are client-side `navigateTo(..., { replace: true })`, the hash kept.
- Pages run under the hashed CSP: no inline `<script>` of our own.
- Storage helpers in `web/app/utils/storage.ts` never throw; callers keep working without storage.
- No feature flag (a rename and an address change, not a feature).
- Commands: repo root `make test` (typecheck + vitest), `make lint`, `make e2e`, `make golden`; in `web/`,
  `npx vitest run <file>`, `npm run e2e -- <spec>` (build + Playwright).
- Stage files by name or directory, never `git add -A`.
- Part 1 is PR 1 (this branch, `song-url`). Part 2 is PR 2, on a new branch from `main` after PR 1 merges.

## Review Focus

1. A visitor's edited library chart (`basedOn: 'autumn_leaves'`) still opens as theirs after the rename. (Task 2 unit + e2e)
2. Storage full or unavailable during the migration: the old key stays, nothing is lost, the page loads. (Task 2 unit)
3. `/song?chart=nope` (unknown legacy chart) → `/`, not a blank editor. (Task 4 e2e)
4. Back button after a legacy redirect doesn't return to `/song?chart=…`. (Task 4 e2e)
5. A new chart added with an underscore or a capital → `make test` fails naming it. (Task 1 unit)

```ts
/** every key in this browser's localStorage (none when it's unavailable) */
export function storedKeys(): string[] {
  try {
    return Array.from({ length: localStorage.length }, (_, i) => localStorage.key(i)).filter((k): k is string => k !== null)
  } catch {
    return []
  }
}
```

`web/app/utils/myCharts.ts`, after `migrateDraft` (import `storedKeys`, `tryWriteStored` from `~/utils/storage` alongside what's imported there now):

```ts
/** a library chart's practice picks and scale level, saved under its name (never `mine:<id>`): csm-practice:<name>:<mode>, csm-level:<name> */
const OLD_NAME_KEY = /^(csm-practice:|csm-level:)(?!mine:)([a-z0-9]+(?:_[a-z0-9]+)+)(:[a-z]+)?$/

/**
 * Chart files were renamed from round_midnight.txt to round-midnight.txt (2026-10): move what this browser saved under
 * the old names. A key that can't be written stays where it was, to try again on the next visit.
 */
export function migrateChartNames(): void {
  for (const key of storedKeys()) {
    const m = OLD_NAME_KEY.exec(key)
    const value = m ? readStored(key) : null
    if (!m || value === null) continue
    const to = `${m[1]}${m[2]!.replaceAll('_', '-')}${m[3] ?? ''}`
    if (readStored(to) === null && !tryWriteStored(to, value)) continue
    removeStored(key)
  }
  const index = readIndex()
  if (index.some((c) => c.basedOn?.includes('_')))
    tryWriteStored(INDEX, JSON.stringify(index.map((c) => (c.basedOn?.includes('_') ? { ...c, basedOn: c.basedOn.replaceAll('_', '-') } : c))))
}
```

`web/app/plugins/chartNames.client.ts`:

```ts

export default defineNuxtPlugin(() => {
  migrateChartNames()
})
```
